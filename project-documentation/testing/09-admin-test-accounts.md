## 1. Architectural Inspection: Administrator Authentication & Multi-Admin Support

Prior to provisioning test accounts, an audit of the authentication and authorization subsystems was conducted:

1. **Database Schema Support (`database/schema.sql`):**
   - The `users` table defines: `role ENUM('alumni', 'admin') NOT NULL DEFAULT 'alumni'`.
   - The database schema does **not** restrict admin accounts to a single record or hardcoded ID. Any user row with `role = 'admin'` and `status = 'active'` possesses full administrative capabilities.
   - Multiple administrator accounts are **natively and fully supported**.

2. **Session & Access Control Logic (`config/db.php` & `includes/auth.php`):**
   - Role evaluation relies on `is_admin()`, which verifies:
     ```php
     function is_admin() {
         return isset($_SESSION['user_role']) && $_SESSION['user_role'] === 'admin';
     }
     ```
   - Server-side route protection is enforced via `require_admin()`:
     ```php
     function require_admin($redirect = null) {
         if (!is_admin()) {
             $target = $redirect ? $redirect : get_base_url() . 'auth/login.php?admin_required=1';
             header("Location: " . $target);
             exit;
         }
     }
     ```

3. **Password Security Standard (`auth/login.php` & `config/create_admin.php`):**
   - All passwords must be stored strictly as standard 60-character Bcrypt hashes (`$2y$10$...`) generated by `password_hash($password, PASSWORD_DEFAULT)`.
   - Login authentication performs cryptographic comparison via `password_verify($password, $user['password'])`.
   - Plaintext passwords are **never** stored or accepted in database tables.

4. **Existing Provisioning Tooling (`config/create_admin.php`):**
   - The application provides a native, CLI-guarded provisioning utility:
     `C:\xampp\php\php.exe config/create_admin.php [username] [email] [password]`
   - This script prevents unauthorized browser access by requiring an authenticated admin session if triggered via HTTP, while permitting local CLI terminal execution.

## 6. Safety & Cleanup: De-Provisioning Test Accounts

When testing is completed, remove the three test accounts from your local database to keep the environment clean.

### SQL De-Provisioning Script:
```sql
USE alumni_network;

-- Safely remove only the dedicated QA test accounts:
DELETE FROM users 
WHERE username IN ('admin_qa1', 'admin_qa2', 'admin_qa3') 
  AND role = 'admin' 
  AND id > 1; -- Safeguard: Never delete primary system administrator ID 1
```

### Safety Rules:
- **Never Commit Test Credentials**: Never commit test accounts or passwords into public Git repositories.
- **Never Use in Production**: These credentials and email domains (`@alumni.test`) are strictly intended for isolated local XAMPP testing.
- **Primary Admin Protection**: As enforced by `admin/users.php`, Primary Admin ID 1 (`admin@alumni.edu`) must remain intact as the system owner.
